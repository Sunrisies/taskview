# GitHub 下载版发布流程

当前可先发布未公证的 Beta 下载包。最终用户只下载 ZIP／DMG，不安装开发工具，也不导入开发者的本地证书。

## 一条命令生成 Beta 附件

在开发者自己的正常 macOS 终端、项目根目录运行：

```bash
python3 Scripts/package_release.py
```

默认重新编译 Release，使用已经安装的固定证书签名，校验后生成 ZIP 和 DMG。签名失败不会改用临时签名，也不会替换旧应用。构建工具需 Xcode 15 或更新的命令行工具（Swift 5.9+）及 Python 3；这些不是最终用户的依赖。

只需要 ZIP，或磁盘映像服务不可用时：

```bash
python3 Scripts/package_release.py --zip-only
```

如果已经在正常终端完成证书签名构建，可以只打包现有应用：

```bash
python3 Scripts/package_release.py --existing --zip-only
```

`--existing` 不保证应用包含最新源码；使用它前自行确认构建时间和版本。签名和结构仍然必须验证成功。

输出示例：

```text
dist/TaskView-1.0.0-beta.1-arm64/
  TaskView-1.0.0-beta.1-arm64.zip
  TaskView-1.0.0-beta.1-arm64.dmg
  SHA256SUMS.txt
  release-manifest.json
  RELEASE_NOTES.md
```

ZIP／DMG 内仅包含 `TaskView.app`、安装说明、隐私说明以及 Applications 快捷方式。不会包含整个开发目录、私钥、开发证书文件、测试截图或编译缓存。应用签名内的公开证书属于签名本身，正常保留。

如果打包中途失败，不发布半成品目录。同一发布目录已经存在时拒绝覆盖，应增加构建号。DMG 生成必须能访问 macOS 磁盘映像服务；不应把替代服务测试通过当成真实 DMG 已验证。

## 版本和签名

保持 Bundle ID `com.zhuzhongqian.taskview` 不变。新版本可设置版本和构建号：

```bash
TASKVIEW_VERSION=1.0.0 TASKVIEW_BUILD_NUMBER=2 python3 Scripts/package_release.py --zip-only
```

版本来自最终应用 Info.plist；Beta 标签由版本和构建号生成，如 `v1.0.0-beta.2`。构建脚本在签名前更新暂存应用，不能直接修改已签名应用的 Info.plist。

本地签名材料保存在被 Git 忽略的 `Scripts/signing/`。已有证书和私钥保留，不覆盖；新克隆需要本地开发签名时，`install_local_signer.sh` 为该开发者生成自己的证书。

当前下载版是未公证测试版。普通用户首次打开时可能被 Gatekeeper 拦截，应在核对来源后按 [Apple 说明](https://support.apple.com/zh-cn/102445) 在系统设置中确认，不要求导入证书或关闭全局安全保护。当前仍需在另一台 Mac 验证安装、权限、自启和窗口操作。

## 上传 GitHub Releases

仓库为 [Sunrisies/taskview](https://github.com/Sunrisies/taskview)，下载入口为 [Releases](https://github.com/Sunrisies/taskview/releases)。已经生成 `dist/TaskView-1.0.0-beta.1-arm64/` 时，可在本机正常终端执行：

```bash
gh auth login                         # 仅首次，登录有仓库写入权限的 GitHub 账号
bash Scripts/publish_github.sh --check-only  # 检查附件校验值与待提交文件，不上传
bash Scripts/publish_github.sh         # 提交源码，推送 main 和版本标签，创建预发布
```

后续版本把发布目录作为参数传入，例如 `bash Scripts/publish_github.sh dist/TaskView-1.0.0-beta.2-arm64`。脚本不会重新签名或覆盖现有附件；会核对 ZIP、校验值、版本和签名，再上传 ZIP、可选 DMG、校验文件及元数据。仅源码、文档、脚本、测试和 `.gitignore` 进入 Git，构建缓存、发布附件及签名材料继续留在本地。遇到已有同名发布或标签、不同远程地址、未合并远程历史时停止，不执行强制推送。

不使用 GitHub CLI 时，可只通过 Git 推送源码和版本标签，然后在网页创建预发布：

```bash
bash Scripts/publish_github.sh --source-only
```

此模式不调用 `gh`，不需要 `gh auth login`，Git 推送仍需本机 SSH 认证和网络可用。推送完成后打开 https://github.com/Sunrisies/taskview/releases/new ，选择脚本输出的标签、勾选 Pre-release，以 `RELEASE_NOTES.md` 为说明，上传同目录的 ZIP、可选 DMG、`SHA256SUMS.txt`、`release-manifest.json`。源码和标签推送成功不代表下载附件已发布。

`gh auth login` 与 SSH 推送认证分别由 GitHub CLI 和本机 SSH 配置管理。远程使用 `git@github.com:Sunrisies/taskview.git`，需要该账号拥有仓库写入权限；不要把 Token、SSH 私钥或签名私钥粘贴进项目。若只完成源码推送而发布失败，脚本会报告失败；可以按下面的网页步骤用已经推送的标签完成发布。

尚未选定源码许可证；公开源码不自动授予他人修改、再分发权限，维护者应在确定授权范围后补充 `LICENSE`。

1. 若发布源码，先选择许可证，确认 Git 提交中不包含签名材料；根目录 `.gitignore` 排除了相关文件和生成目录。不要直接把整个开发目录作为下载包上传。
2. 在 GitHub 仓库的 Releases 页面创建新版本，标签使用包内记录的版本，例如 `v1.0.0-beta.1`。
3. 勾选预发布（Pre-release），用生成的 `RELEASE_NOTES.md` 作为说明。
4. 上传 ZIP、可选 DMG、`SHA256SUMS.txt` 和 `release-manifest.json`。
5. 在另一台 Mac 上通过浏览器重新下载，移入“应用程序”，验证系统首次打开和权限授权流程后再广泛推荐。

`package_release.py` 只生成本地附件；`publish_github.sh` 负责提交、推送和发布，不创建远程仓库。[GitHub Releases 说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

## 正式签名并公证的版本

以后持有 Developer ID Application 身份时，构建脚本支持 Hardened Runtime 和安全时间戳：

```bash
TASKVIEW_DISTRIBUTION=developer-id \
TASKVIEW_SIGNING_IDENTITY='Developer ID Application: 你的名称 (TEAMID)' \
./Scripts/make_app.sh
```

然后按 [Apple 公证工作流](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) 提交公证并将票据装订到应用。公证完成后打包：

```bash
python3 Scripts/package_release.py --existing --channel stable
```

`stable` 仅在 Developer ID 身份、Hardened Runtime、公证票据和系统执行评估全部通过时生成附件；不能把本地自签名 Beta 标成已公证正式版。当前没有提供 Apple 公证账号凭据，也没有执行上传公证。
