# 常驻性能与后续计划

## 当前结论和证据边界

从代码看，TaskView 适合事件驱动的菜单栏常驻：空闲时没有窗口扫描定时器、键盘轮询、持续录屏或周期网络请求。全局热键由系统事件回调触发，只有打开任务视图才获取窗口和截图。

本次检查环境不允许执行 ps 读取进程统计，所以没有取得用户当前实例的真实 CPU、RSS 或数小时运行数据。以下内存数字是缩略图像素估算，不是应用总内存实测；不能据此宣称零 CPU、零泄漏或长期驻留已经通过压力测试。

本次已完成的性能相关改进：

- Release 默认不写文件诊断日志；需要时用 `--debug-log` 开启。Debug 默认开启。
- 开启日志后，后台串行写入并轮转。当前文件和单份备份各最多约 1 MiB；首次遇到旧版超大日志时只保留尾部。
- 鼠标悬停选择只更新前后两张卡片，避免每次 O(n) 刷新整个网格。
- ThumbnailLoader 只截取当前可见卡片，滚动时释放离开视口的图片；截图最多四个同时进行，快速开关时也保留旧截图槽位直到系统返回。
- 搜索和分组只处理已有元信息，不扫描系统或截取所有匹配窗口。
- 没有可见或正在加载的覆盖层时，关闭操作直接返回，减少失焦通知中的无效工作。

## 空闲与打开时的负担

| 阶段 | 当前行为 | 性能含义 |
| --- | --- | --- |
| 菜单栏空闲 | 等待热键、菜单或系统激活事件 | 自身没有定时唤醒循环；系统框架仍可能产生事件。 |
| 打开任务视图 | 读取窗口列表，查应用图标，布局全部卡片 | 工作量随窗口数增长；首次框架加载也有成本。 |
| 缩略图加载 | 四路单次截图、等比缩小，仅存当前可见卡片 | 并发上限限制瞬时工作量，图片驻留随可见卡片数增长，不再随累计浏览窗口数持续增加。 |
| 任务视图保持打开 | 显示静态截图、响应鼠标键盘 | 窗口内容不会实时刷新；模糊、合成和屏幕重绘仍可能消耗 GPU。 |
| 关闭任务视图 | 移除卡片、取消加载与截图，保留覆盖层窗口 | 释放图片引用，但框架缓存、窗口背板和 RSS 不一定立即回落。 |
| 设置窗口 | 显示系统状态；用户修改后保存 | 普通控件常驻，无周期权限探测；连续拖动滑块会连续保存。 |

按每像素 4 字节粗略估算，最长边限制为 L 时，单张正方形缩略图最多约为 `L × L × 4`：

| 清晰度 | 单张正方形像素数据 | 20 张同时可见 | 50 张同时可见 |
| --- | ---: | ---: | ---: |
| 480 | 0.88 MiB | 17.6 MiB | 43.9 MiB |
| 960 | 3.52 MiB | 70.3 MiB | 175.8 MiB |
| 1440 | 7.91 MiB | 158.2 MiB | 395.5 MiB |

实际普通横向窗口面积通常小于正方形上限，但 AppKit、截图缓冲、图片对象和 GPU 纹理会额外占用内存，不能把表格当成总进程内存上限。四路并发不会把可见图片总内存限制为四张；可见区域以外最多还有四个尚未完成的系统截图。

日常可先用标准 960；窗口较多时选择 480。1440 更适合少量窗口且需要看清内容的情况。

## 本机测量方法

打开 Release 应用，关闭任务视图和设置窗口，在自己的 macOS 终端运行：

```bash
cd /path/to/TaskView
python3 Scripts/profile_idle.py --duration 60 --interval 5
```

脚本自动寻找 TaskView；如果同时运行多个实例，指定活动监视器中对应实例的 PID：

```bash
python3 Scripts/profile_idle.py --pid 12345 --duration 3600 --interval 30
```

每份结果立即保存到 `build/performance/idle-日期时间.csv`，输出 RSS 起止值、峰值和测量区间平均 CPU。CPU 由累计 CPU 时间差除以实际经过时间计算，一个核心全部占用记为 100%。短测量可能因 ps 的时间精度而看起来为 0，不能代表绝对没有 CPU 使用。

建议分别测量：

1. 启动后静置 60 秒，确认基线。
2. 连续驻留一小时以上，中间不打开任务视图，检查 CPU 和 RSS 是否持续增长。
3. 重复打开关闭约 30 次，等待系统截图结束再采样，比较关闭后的 RSS 是否稳定在一个平台，而非每次持续上升。
4. 分别用 480、960、1440 清晰度，保持相同窗口数量比较。

该脚本只测 CPU 时间和 RSS，不测 GPU、唤醒次数、能耗、截图延迟或图片对象泄漏。长时间问题需结合活动监视器的“能耗”、Xcode Instruments 的 Allocations / Leaks / Time Profiler；进程 RSS 不下降本身不能证明泄漏。

## 仍需关注的问题

| 问题 | 当前状态 | 建议 |
| --- | --- | --- |
| 可见截图内存 | 已改为仅截取可见卡片并释放离开视口的图片 | 若大屏同时可见卡片很多，再增加像素预算和自适应清晰度。 |
| 多屏与全屏空间 | 已提供当前 / 所有显示器筛选，覆盖层显示在打开时鼠标所在屏幕 | 坐标转换有测试；多屏、全屏空间仍需实机验证。 |
| 最小化窗口 | 目前仅取在屏幕上的窗口 | 若要包含最小化窗口，需额外枚举、恢复与无截图占位逻辑。 |
| 同名或无标题窗口 | 按唯一标题与几何信息选择；并列不精确聚焦 | 保留保守行为并验证常见应用，几何匹配仍存在局限。 |
| 关闭或移动后的窗口 | 读取时快照可能在点击前失效 | 打开目标前再验证，失败时提示或刷新列表。 |
| 截图失败 | 保留应用图标，截图错误目前没有逐卡提示 | 增加“截图不可用”状态和重试入口，区分权限撤销与窗口已关闭。 |
| 系统权限状态 | 实际接口结果与预检查结合；支持手动复查 | 系统设置勾选不保证当前签名和路径已生效；授权状态需要当前应用验证。 |
| 发布支持 | 已有 Beta ZIP / DMG 打包、安装和隐私说明；本地证书、arm64、未公证 | 他机验收仍待完成；以后补 Developer ID 公证和通用架构。 |
| 长期驻留 | 代码路径已审查，真实小时级采样尚未取得 | 先测量再决定是否增加定时清理，避免引入不必要的轮询。 |

## 本次已新增

- 标题 / 应用名搜索，支持中文和多个关键词；直接输入或 ⌘F 聚焦，输入法组合期间保留原生处理；搜索框内 ↑ ↓ 选择结果、回车确认、Esc 清空后再关闭。
- 当前显示器 / 所有显示器筛选，当前屏幕取本次打开时鼠标所在屏幕；跨屏窗口按相交规则包含。
- 按应用进程分组，应用组按首次出现排序，组内保持窗口前后顺序；带组标题，键盘可跨组导航。
- 可见卡片截图，滚动、搜索和分组时优先加载新视口，清除旧图片；保持四路并发和旧回调隔离。

显示器范围和分组可从任务视图顶部立即切换并保存，也可在设置中修改默认值。新增字段兼容旧版保存数据，不重置已有快捷键。

关闭操作在后台执行，辅助功能单次通信设置超时，枚举有时间预算，不增加空闲轮询。

## 后续可增加

应用排除名单、最近使用排序和截图失败提示尚未实现。窗口关闭按钮已实现，通过辅助功能请求原生关闭，保留目标应用的未保存文件确认。

截图目前离开视口即淘汰，反向滚动会重新截图。可进一步加入有像素预算的短期缓存，减少来回滚动的成本，但需要过期、窗口关闭、尺寸变化和权限撤销时失效。

实时预览、多桌面管理和拖动窗口到桌面属于更大的扩展。实时预览会改变常驻能耗，多桌面操作受公开系统接口限制，适合在核心切换体验稳定后另行评估。
